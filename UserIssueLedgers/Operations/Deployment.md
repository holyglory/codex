# User Issue Ledger: Operations / deployment

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
|---|---|---|---|---|
| UIL-OPERATIONS-DEPLOYMENT-001 | Live Codex deployment from a remote UI task | Draining the active app-server before switching the release link allowed the remote UI to reconnect to the old binary repeatedly; the detached helper failed after an hour and the user received no timely result. | For an explicitly approved self-terminating deployment, finish package validation first, preserve rollback evidence, atomically make the verified new release the reconnect target, and only then terminate the exact old-release sessions. Report a failed handoff promptly and never imply activation before the installed version is verified. | Before activation, prove every targeted Codex process belongs to the approved account and old release. Verify the new archive and rollback hashes, atomically activate the immutable release, terminate only the previously identified old-release sessions, and confirm the new launcher version plus process executable paths after reconnect. A reconnect race must fail within a bounded interval with the old release still active or use the reviewed activate-before-drain sequence. |
| UIL-OPERATIONS-DEPLOYMENT-002 | Existing desktop tasks after an app-server restart or unload | Verifying saved-history reads after deployment misses a desktop that still sends input to an unloaded task, which reports `thread not found` despite intact history | Restore the saved task and its client response subscription before accepting new input; a stale steer must not silently start another turn, replay work, or discard the message. Preserve archive, parent ownership, configuration, and single-writer rules | Exercise new input and stale steering after a real server restart, including repeated restarts; verify ordered responses, unchanged prior history, one accepted message per submission, honest missing/archived/owned-task failures, and posting through the original desktop task before claiming that surface repaired |
