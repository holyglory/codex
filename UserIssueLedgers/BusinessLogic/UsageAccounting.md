# User Issue Ledger: Business logic / usage accounting

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-BUSINESS-LOGIC-USAGE-ACCOUNTING-001 | Current-repository usage lookup across CLI, TUI, app-server, and agent reports | Resolving only one repository identity candidate, or selecting remotes differently during capture and query, fails when history used another verified identity source available for the same checkout | Derive remote identity consistently (`origin`, otherwise the same first verified remote), then check verified candidates in authority order—normalized remote, Git common directory, canonical workspace—and follow only existing explicit merge history without persisting raw identity material or mutating identity history during a read | Capture isolated usage under each identity-source availability combination, including a checkout with only a non-`origin` remote; query it from the same checkout with richer and poorer metadata through the real CLI `current` path; assert the matching stored report, and prove path reuse or remote changes remain separate with no implicit merge while privacy tests continue to exclude paths and remotes |
| UIL-BUSINESS-LOGIC-USAGE-ACCOUNTING-002 | Human and in-product-agent access to advanced local collector reports | Treating a reduced aggregate or a small subset of convenient record lists as complete access hides approved stored dimensions from one supported caller | Preserve every approved content-free aggregate and stored detail dimension in versioned structured CLI JSON and a bounded credential-free in-product agent surface; inventory every usage schema table/column, explicitly exclude process OS PIDs and prohibited/raw data, paginate record families, and never substitute synthetic totals | Maintain a schema-to-interface inventory covering repository/thread/turn/agent/operation/model-request/token/tool/approval/repository-attribution/classification/coverage/activity-span/lifecycle/retry-rework dimensions; round-trip representative complete records through focused CLI and built-in-tool tests with pagination, bounds, current-chat/current-repository/account filtering, and assertions that raw content, credentials, paths/remotes, service/workspace IDs, and process PIDs are absent |
| UIL-BUSINESS-LOGIC-USAGE-ACCOUNTING-003 | Required usage capture in long-lived CLI, TUI, app-server, and delegated-agent processes | Latching one transient or operation-scoped accounting write failure for the entire process makes every later model operation fail even after the private database is healthy again | Retry a bounded recoverable failure before exposing it, preserve a content-free coverage gap, conservatively terminate only affected incomplete operations, and automatically restore healthy capture; corrupt storage and unrecoverable invariants remain fail-closed without poisoning unrelated valid metadata | Reproduce a recoverable write failure in the shared runtime, prove the same submitted operation proceeds after storage health returns, verify affected incomplete facts become interrupted/partial without touching concurrent operations, prove a late terminal callback cannot relatch recovery, and retain corruption and invalid-metadata fail-closed coverage through focused store, core, and rendered app-server/CLI checks |
| UIL-BUSINESS-LOGIC-USAGE-ACCOUNTING-004 | Repository token attribution and breakdowns across CLI, TUI, app-server, and agent reports | Treating every writable workspace root as a participating repository turns ordinary project requests into `multi_repo`; per-repository reports then exclude the newly classified tokens and can misleadingly show only older, 100%-unknown usage, as seen in DesignDocEngine | Attribute tools only to a repository proven by their active runtime scope; mere permission to access an auxiliary output root is not participation. Preserve truthful partial or unknown coverage for genuinely unattributable history and never manufacture a repository assignment after the fact | Capture classified provider usage with a project checkout plus an auxiliary writable Git root and prove the project remains a single-repository token bucket; also exercise genuine multi-repository runtime scopes, query per-repository and all-repository rendered views and structured reports, assert historical unknowns stay separately visible, and prove no repository receives another repository's usage |
| UIL-BUSINESS-LOGIC-USAGE-ACCOUNTING-005 | Release readiness for all-history usage reporting across CLI, TUI, app-server, and agent tools | Treating a fast warm-cache report as completion while a production-sized cold report still takes 125 seconds—and while its request-related completion-ledger task remains open—overstates readiness | A release is complete only when cold and warm production-sized reports meet the agreed interactive behavior, preserve every approved dimension and exact total, and the authoritative ledger has no request-related unfinished item; do not demote an acceptance gap into a non-blocking follow-up | Benchmark isolated production-sized cold and warm collectors with identical output digests, stage-level timings, bounded CPU and memory, privacy assertions, and false-positive guards; reconcile the authoritative ledger immediately before every completion claim and keep readiness open while any request-related row remains unfinished |
