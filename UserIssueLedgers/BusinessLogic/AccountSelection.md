# User Issue Ledger: Business logic / account selection

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-BUSINESS-LOGIC-ACCOUNT-SELECTION-001 | Automatic profile selection at CLI, TUI, app-server, and remote-UI turn boundaries | Enabling automatic selection with valid authenticated profiles lets an empty or stale process-local rate-limit cache abort every turn before the process refreshes limits; refreshing in another process cannot repair that cache | Before automatic selection, fetch missing or stale limits under each eligible managed-ChatGPT profile lease, coalesce concurrent refreshes, use fresh successful observations, and return a content-free error only when no eligible profile can be established; never enter excluded auth modes or start model/tool work during refresh | Exercise a realistic three-profile app-server turn with stale and missing cache entries, per-profile rate-limit mocks, partial refresh failure, and concurrent first turns; assert the selected lease, bounded refresh calls, no model request before selection, honest failure when every refresh fails, and the original SSH/UI surface after deployment |
| UIL-BUSINESS-LOGIC-ACCOUNT-SELECTION-002 | Service-capacity classification for ChatGPT subscription profiles | Treating `credits.has_credits=false` as total exhaustion even when the subscription rate-limit window is explicitly below 100% rejects valid Pro profiles that merely have no purchased top-up credits | Explicit server reached types and spend controls remain authoritative; an open subscription window proves eligibility despite absent top-up credits, while depleted credits are a reached fallback only when no usable window or positive-credit evidence exists | Cover open-window/no-top-up, no-window/depleted-credit, explicit credit-depleted reached type, full window, spend control, and the live three-profile response shape; retest automatic selection against the real service after deployment |
| UIL-BUSINESS-LOGIC-ACCOUNT-SELECTION-003 | Automatic profile selection observed through the remote UI and app-server event stream | Publishing the automatic-switch warning before the selected account's response items can make the remote UI discard or displace a verbose agent response even though the server eventually persists it | Pin the submitted turn and response stream to one immutable account snapshot, deliver every agent-message delta and completed item first, then publish the automatic-switch notice at the terminal edge before `turn/completed` | Exercise app-server JSON-RPC with a selected non-default profile and a multi-chunk verbose response; assert the backend request uses the selected profile, the remote client receives the full ordered deltas and completed message before the switch notice, `turn/completed` retains the same text, and no response item is lost or duplicated |
| UIL-BUSINESS-LOGIC-ACCOUNT-SELECTION-004 | Automatic profile selection during long CLI, TUI, app-server, and remote-UI turns | Treating a pre-response usage-limit rejection as a terminal turn failure makes unattended work stop even when another authenticated profile has capacity; manual resume then proves the same history can continue on the backup profile | After recording the rejected profile's reached limit, retry the still-pending sampling step on another eligible managed-ChatGPT profile only when the rejected attempt emitted no response item or tool side effect; preserve completed history, bind every real request and its usage to its factual profile, and keep partial streams, process pins, and genuinely exhausted pools explicit failures | Exercise an app-server turn that completes model/tool cycles before a later sampling request receives a usage-limit rejection with no output; prove bounded failover continues the same turn, request and usage ownership change truthfully, no prior tool call/output or agent text is replayed, and the switch notice follows the complete response. Also prove no failover after partial output, under a process pin, or when every eligible profile is exhausted |
| UIL-BUSINESS-LOGIC-ACCOUNT-SELECTION-005 | Voice startup and control connections from the remote UI, including SSH app-server sessions | Resolving managed profiles only for text turns leaves voice startup on an empty legacy auth manager, sending unauthenticated requests to the API endpoint despite a valid ChatGPT profile | Resolve voice authentication through the existing profile selector before creating or attaching a call; honor process pins and external-auth boundaries, retain the selected profile lease for the call lifetime, and use matching credentials for call creation and sideband reconnects without requiring another API key | Exercise remote-client JSON-RPC voice startup with profile-only credentials and no preceding text turn; verify ChatGPT and API-key routing, changed defaults, process pins, automatic selection and honest selection failure, matching sideband authentication, and lease release after stop; verify the original SSH UI before claiming resolution |
